# Unreleased

Changes that should be included in the next release go here. Keep this file current during normal development; move the relevant notes into `docs/releases/<version>.md` only when preparing a release.

## Added

- The MCP server can now serve over HTTP as well as stdio, so it can run while the desktop app does. A new **MCP Server** panel on the desktop Config page hosts an opt-in toggle: while enabled, the app serves the same four read-only tools on `http://127.0.0.1:<port>/mcp` (default port 20151, editable in the panel), guarded by a bearer token stored owner-readable-only at `<config dir>/tokenuse/mcp-token` (delete the file to rotate it). The panel shows the endpoint, running state, and masked token with reveal/copy buttons, plus a copyable `claude mcp add` command; the token never travels in the background snapshot poll. The CLI gains the matching foreground mode — `tokenuse mcp --http [--port N] [--real-names]` — and the TUI Local Files panel's MCP hint reflects the configured HTTP state. The listener binds loopback only, requires the token on every request, rejects non-localhost `Host`/`Origin` headers (DNS-rebinding defence), and makes no outbound calls; project names stay pseudonymised (the desktop endpoint always; `--real-names` remains CLI-only).
- Scrollback: full-text search across every archived session transcript, on both surfaces. The TUI gains a Scrollback tab (`/` from any page opens it with the search input focused; type a phrase, press Enter) and the desktop a Scrollback sidebar page (search-as-you-type with tool and project filters). Results group per session with role-tagged, term-highlighted snippets and a match count; opening one drills into the full session view, and returning restores the query and results. Search honours the tool and project filters and always reads the live archive, even in sample-data mode.
- To power Scrollback, all five tool parsers now capture full user and assistant turn text (thinking/reasoning text stays excluded everywhere) into a transcript store with an SQLite FTS5 index inside `archive.db` (schema v7). Existing archives migrate automatically: already-archived truncated prompts are seeded as prompt-only fallbacks so sessions whose source files are gone stay searchable — badged "prompt only" in results — and surviving sources re-parse once to upgrade to full text.
- `tokenuse mcp` gains a fourth tool, `scrollback`: full-text transcript search with a required `query` plus optional `project`, `tool`, and `limit` arguments. Results carry each matching session's tool, project, last timestamp, cost, match count, and plain-text snippets. Project labels follow the projects tool's pseudonymisation (and a pseudonym is accepted as the project filter); snippets are raw transcript text, since the client is reading its own local sessions.
- The Config page's Clear Data row on both surfaces now leads with the archive size (for example `Archive 12.3 MiB incl. transcript index`) once `archive.db` exists, so transcript-index growth stays visible; Clear Data remains the purge path for captured transcripts.
- The desktop Coach page gains an advisory Setup panel: unused configured MCP servers, CLAUDE.md files over 200 lines after `@import` expansion, repeated file re-reads inside sessions, and reads under build/dependency directories — each with a heuristic token-savings estimate. Setup findings never affect the practice grade.
- Spend is now broken down by activity: every call is classified into one of thirteen deterministic task categories (coding, debugging, feature dev, refactoring, testing, exploration, planning, delegation, git ops, build & deploy, brainstorming, conversation, general) from its tool usage and prompt — no LLM involved. A "By Activity" panel appears on the desktop Analytics page, the TUI Deep Dive page, and in `tokenuse overview`.
- Reports now carry the same task-category breakdown: JSON gains a `task_categories` block, Excel a "By Activity" sheet, and the CSV folder a `task_categories.csv`, each row with the category label, calls, tokens, and cost.
- Models silently billed at the fallback pricing rate are now surfaced instead of blending in: the Config page (TUI and desktop) warns with the affected `tool · model` pairs and the fix hint, and report metadata (JSON, Excel, CSV) carries a `fallback_priced_models` row.
- `tokenuse status` and `tokenuse overview`: scriptable summaries without the TUI. `status` is a one-liner with rolling-24-hour and month totals; `overview` is a copy-pasteable month summary (totals, tokens, per-tool spend, top models and projects, daily table). Both respect the configured currency and take `--json` for machine output.
- Claude Code sync is now incremental at the byte level: grown session files resume from a stored per-file byte offset (with a prefix probe guarding against rewrites) instead of re-parsing every session in the project directory. On a ~50MB real project a one-file append resyncs in ~0.04s versus ~0.4s before, with byte-identical archive contents. The sync status line on both the TUI and desktop appends `· N tail-resumed` when it happens; other tools keep the full-reparse path (their formats need whole-file context).
- New Coach rule "Retry Loops" (session hygiene, medium): flags periods where a high share of edited files needed a re-edit after a shell run — the change didn't survive its own verification. Detection is per session and file at assistant-round granularity, only for tools that report edited files (Claude Code, Codex, Cursor); re-edits without an intervening shell command never count.
- The TUI gains a Coach page (`k`, or Tab-cycle): overall grade, per-group scores, triggered findings with their occurrence lines, and the advisory Setup panel — the same data and copy as the desktop Coach page, honouring the active period, tool, and project filters.
- Plan-value tracking: Usage consoles (TUI and desktop) now show what the calendar month's tokens would have cost at API prices against the tool's monthly subscription price, with the resulting value multiple. Prices are configured in the desktop Config page's Plan Value panel (stored as `plan_prices` in `config.json`, USD); detected ChatGPT Plus/Pro and Copilot Pro/Pro+ plans get a built-in default until one is set, and org-paid tiers never do.
- `tokenuse mcp`: a read-only MCP server over stdio for LLM clients. Exposes `status`, `overview`, and `projects` tools with the same numbers as the scriptable CLI summaries; project names are pseudonymised with a locally persisted salt unless started with `--real-names`. No network, no new dependencies; the Config page (TUI Local Files and desktop Local Data) shows the launch hint.
- `tokenuse doctor`: read-only per-tool diagnostics. Shows every location each adapter probes (and whether it exists), the environment overrides in effect, discovered session/limit source counts, and a bounded parse sample, ending in an `OK` / `NOTHING FOUND` / `ERRORS` / `DISCOVERY FAILED` verdict with the likely cause. `--json` emits the same report machine-readable.
- The same diagnostics reach the desktop: a Data Sources panel on the Config page runs the doctor report on demand (never from the background poll) and renders per-tool verdict badges, probed locations with found/missing state, env overrides, source counts, and parse-sample results.
- The desktop Config page's fallback-pricing warning is now warning-toned instead of blending into the pricing row's plain value text.
- Codex sessions archived from the Codex UI (`~/.codex/archived_sessions/`) are now discovered and ingested, so archiving a session no longer removes its history from the dashboard.
- Copilot in VS Code now reads the Copilot Chat extension's OpenTelemetry span store (`agent-traces.db`) — the one VS Code source with real input, output, and cache token counts — plus VS Code core chat-session journals (`chatSessions/`, real prompt/output counts) and the global empty-window journals. Per VS Code variant the most authoritative source wins, so estimates never double count real data. VSCodium storage paths are now covered alongside VS Code and VS Code Insiders.
- Legacy Copilot CLI sessions now recover real input and cache token counts from their `session.shutdown` per-model rollups; previously those sessions reported input as 0 and their cost was output-only.
- Cursor input tokens now come from Cursor's own per-conversation context meter (`promptTokenBreakdown`) when bubbles carry no explicit counts — credited once per conversation on a stable anchor instead of chars/4 guesses per turn. The meter is a latest-snapshot figure, so totals can undercount the Cursor admin console but never double count.
- Cursor conversations now resolve their project from VS Code workspace storage (the workspace folder each composer was opened in), so state-backed conversations group under their real repository instead of the generic workspace label.
- Cursor's Composer house models now all price at Cursor's published rates: `composer-1` from the live pricing table, and the retired `composer-1.5` / `composer-2` pinned in the sources manifest. Previously anything older than Composer 2.5 fell through to the global fallback model.
- Claude Code advisor runs are now counted: each `advisor_message` iteration inside a message's usage payload is a separately billed API call with its own model and token buckets, and now appears as its own call in totals, model breakdowns, and session views.
- Claude Code 1-hour cache writes now price at Anthropic's published premium (2x base input versus 1.25x for the 5-minute TTL). Sessions using long-TTL prompt caching were previously underpriced by 1.6x on their cache-write spend.
- Session-scoped Claude Code subagent transcripts (`<project>/<session-id>/subagents/agent-*.jsonl`, written by newer Claude Code builds) are now discovered and ingested.

## Changed

- Top Sessions rows now link to the session view on both surfaces. On the desktop, rows on the Analytics page and the per-tool pages open the full session view (click, `Enter`, or `Space`), and closing it returns to the page it was opened from, restoring the scroll position you left — the back button names that page instead of always saying Analytics. In the TUI, clicking a Top Sessions row on Deep Dive opens that session's page, the same drill-down the `s` picker reaches.
- The desktop Projects page is now a two-level drill-down. The page itself is a full, uncapped index of every project in the period — cost, avg/session, sessions, calls, last active, and tool mix per row. Selecting a row, or any project row on Overview, Analytics, or a tool page, opens that project's dedicated page: KPIs (cost, calls, sessions, cache hit, AI code output, estimated active hours with the work-pattern note), the activity pulse, the full session list (rendered incrementally, each row opening the session view), a per-tool split donut switchable between cost, calls, sessions, and avg/session (a single-tool project shows that tool's numbers plainly instead of a one-slice ring), top models, By Activity task categories, core tools, shell commands, MCP servers, and the raw per-tool source paths discovery found. In the TUI, clicking a By Project row on Deep Dive applies that project as the active filter (clicking it again clears back to All), matching the `p` picker.
- The desktop Tools screen no longer repeats the full per-tool consoles that already live on each tool's dedicated page. It is now a rolling 24-hour overview: one compact KPI card per tool with cost, activity pulse, calls/tokens/last-seen, primary limit gauges with reset times, and the plan-value line, and each card opens that tool's page. Cards order busiest-first by rolling 24-hour calls (the same dynamic order as the sidebar tool rows), and the busiest tool's card spans the full row as a spotlight with limit plans and its top models. In the sidebar, Tools moves down to sit directly above the Claude Code/Cursor/Codex/Copilot/Gemini rows it summarizes (Tab-cycle order follows). The TUI Usage page is unchanged — it remains the terminal's only console surface.
- The desktop Analytics page's spend-by-tool stack switches to hourly buckets on the 24 Hours period (titled "Hourly spend by tool"); the rolling window previously collapsed into one or two daily bars. Other periods keep daily buckets.

- Ranked tables on both surfaces (desktop Top Projects, Top Models, Model Efficiency, By Project, By Activity, sessions, project/tool rows, commands, MCP servers, the Models catalog, and the Coach output breakdown; the matching TUI panels) drop the leading rank-meter column and instead paint each row's relative magnitude as a muted blue wash across the row background with a thin terminus edge. The reclaimed column width goes to project and model names, which were truncating in the side-by-side panels; exact percentages move to row tooltips and screen-reader text. The segmented meter remains only in the usage-console and tool-card model rows, where it sits mid-row.
- Desktop cards that share a grid row now stretch to equal height on every page (Overview, Analytics, Coach, Tools, Models, Projects, Config), so side-by-side panels end on one flush bottom edge instead of ragged content-sized bottoms. Capped data lists still scroll internally at 480px. The Daily Spend by Tool chart also stops clipping its first and last date labels.
- Claude Code parsing now merges every streamed JSONL line of an assistant message into one call. Claude Code writes one line per content block (same message id and usage on each), and the previous first-line-wins deduplication silently dropped the tool calls, shell commands, edited/read files, and response text carried on later lines. Token counts and costs are unchanged; Core Tools, MCP Servers, shell command counts, and Coach signals become noticeably more complete after the automatic reparse.
- Nested Claude Code workflow subagent transcripts (`subagents/workflows/<workflow>/agent-*.jsonl`) are now ingested; previously only the top level of each `subagents/` directory was read, so workflow runs under-reported spend.
- Codex calls are deduplicated by session lineage (content-addressed cumulative totals) instead of file path. Rollouts forked in the Codex UI replay the parent session's history into the new file, which the old path-scoped keys double-counted; replays now collide with the parent's rows and usage written within the fork-creation window is dropped. Existing archives migrate automatically on the next sync: each reparsed call retires its legacy row and keeps that row's import-time cost, so history is not repriced.
